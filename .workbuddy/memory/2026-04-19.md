## 国服OAuth认证方式分析（参考 zhkrb/Eve-Android-loginDemo）

### 核心发现
- 国服（网易）**只支持 OAuth 2.0 Implicit Flow**，不支持 Authorization Code + PKCE
- 公用 Client ID：`bc90aa496a404724a93f41b4f4e97761`
- redirect_uri：`https://esi.evepc.163.com/ui/oauth2-redirect.html`
- Token 直接从重定向 URL 的 `#access_token=` Fragment 中提取，无需二次 POST /token
- 授权 URL 额外需要 `realm=ESI` 参数（device_id 可选）
- EVEMon 当前使用 PKCE + `client_id=05153596...` + `localhost:4916/callback`，与国服完全不兼容
- 修复方向：Seren 模式下改用 Implicit Flow + 公用 Client ID + ESI redirect_uri

### 本次会话续 (2026-04-20 下午)

**国服OAuth认证修正（参考 Pyfa）**：

之前实现的 Implicit Flow 失败，参考 Pyfa 项目后发现关键差异：

1. **redirect_uri 域名不同**
   - 错误: `https://esi.evepc.163.com/ui/oauth2-redirect.html`
   - 正确: `https://ali-esi.evepc.163.com/ui/oauth2-redirect.html`

2. **使用 Authorization Code 模式而非 Implicit Flow**
   - 错误: `response_type=token` (Implicit Flow)
   - 正确: `response_type=code` (Authorization Code Flow)

3. **固定的 state 和 device_id**
   - state: `hilltech` (固定值)
   - device_id: `eims` (固定值)

4. **Seren 支持 refresh_token**
   - Authorization Code 模式会返回 refresh_token
   - 可以实现 token 自动刷新

**修改的文件**：
- `NetworkConstants.resx`: redirect_uri 和授权 URL 模板
- `SSOAuthenticationService.cs`: 支持 Authorization Code 换取 token
- `ManualTokenInputForm.cs`: 支持从回调 URL 提取 code 参数

**关键发现：必须先清除旧的 session**

参考 Pyfa，发现 **Seren 服务器认证必须先访问 `/account/logoff` 清除旧的 CCP session**，否则会报 `Missing Netease token` 错误。

Pyfa 的流程：
```python
if server.name == "Serenity":
    webbrowser.open(config.SSO_LOGOFF_SERENITY)  # 先清除 session
    time.sleep(1)
webbrowser.open(uri)  # 然后打开授权 URL
```

已修改 `ManualTokenInputForm.openBrowserButton_Click`，在打开授权 URL 之前先打开 `https://login.evepc.163.com/account/logoff`。

**进一步发现：Seren Authorization Code 模式需要发送 code_verifier**

参考 Pyfa，即使 Seren 不使用 code_challenge（因为没有在授权 URL 中发送），但在兑换 token 时仍需发送 code_verifier。

已修改：
- `SSOAuthenticationService` 添加 `m_codeVerifier` 字段
- 构造函数中为 Seren 服务器也生成 code_verifier
- `VerifyAuthCode` 中 Seren 分支添加 `code_verifier` 参数
